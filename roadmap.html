Roadmap · 实施路线

先跑通数据模型，再叠加资金流

顺序本身就是风险控制。MVP 阶段引入代币化或真实资金流，会把合规复杂度提前引爆；而碳基线数据模型如果一开始建错，后面每一层都要返工。

01 PHASES

每阶段的范围、交付物与验收门

P1
3–4 月 · MVP

孵化 + 项目展示 + 碳预备档案

不做真实资金流，不产生碳信用。目标：跑通项目入驻与碳档案数据模型。

  • 项目方门户、项目注册与诊断、孵化任务流
  • 简化碳基线：因子库 + 分环节测算 + 减排潜力评分
  • 社区预热页与预约投资（无支付）
  • Admin：项目审核、上下架、基础报表
GATE 1
≥ 10 个真实项目完成碳基线录入，其中 ≥ 3 个数据可支撑后续核证材料；CarbonProfile 模型未发生结构性返工。
P2
4–6 月

社区众筹 + 基础碳台账

碳权益层先做「台账视图」：手动记录核证量、手动分配、手动注销标记，不接登记簿 API。

  • 发行页、认购状态机、托管对接、投资者组合页
  • SPV 记录与碳权益穿透比例
  • 项目详情页「股权 + 碳权益」同页呈现
  • 手动台账：批次、分配、注销标记（带排他字段）
GATE 2
完成 1 个真实社区轮（或等效沙盒演练），全流程资金可追溯；用户测试中 ≥ 70% 能正确区分「投资」与「碳权益」。
P3
6–9 月

MRV 工作流 + 登记簿 API + 机构数据室

碳权益分配与注销走通端到端。这是整个平台技术含量最高的一段。

  • 核证方门户、七步状态机、审计轨迹、证书生成
  • Verra / Gold Standard 至少一家 API 对接（含对账任务）
  • 机构门户、数据室权限、水印与下载日志
  • 基金与 SPV 基础管理（不含 carry）
GATE 3
至少 1 个批次完成「核证 → 登记簿签发 → 分配 → 注销」全链路，且与登记簿余额连续 30 天对账一致。
P4
9–12 月

基金全生命周期 + 双重收益 + 合规加固

从「能跑」到「能被审计」。

  • capital call、NAV 估算、carry 瀑布（双口径）
  • 退出事件、对价拆分、分配执行
  • 企业披露支持包、双重计算强制校验
  • 完整审计报表、风控看板、合规工作流配置器
LAUNCH 门
外部审计或顾问复核通过；守恒校验在压力测试下 0 漏检；三实体合同与资金流书面确认无混同。
02 METRICS

关键成功指标：四组，别贪多

每组只保留能驱动决策的指标。看板上的数字如果没人据此做决定，就该删掉。

维度指标定义 / 口径用来看什么
项目供给入驻项目数通过审核的 Project 计数供给端是否有真实货源
碳基线完成占比完成基线 / 入驻总数可测量化能力，低于 60% 说明表单或支持不够
孵化 → 融资转化率进入众筹或机构层的项目 / 完成孵化项目孵化层是否真的在筛项目，而非囤项目
资本栈众筹成功率达标交割轮次 / 上线轮次定价与叙事是否被市场接受
机构层单项目平均融资额机构轮金额 / 项目数机构信任度
基金 AUM承诺资本 + 已到位资本规模化能力
碳权益核证吨数 / 已分配 / 已注销三个数并列展示，不合并碳层是否在真实运转
碳权益合同覆盖率含碳权益条款的融资项目 / 融资项目总数差异化是否被写进交易文件
核证周期提交 → 签发的天数中位数MRV 流程效率
风险核证驳回率驳回批次 / 提交批次项目质量与核证方严格度
双重计算告警次数目标值恒为 0任何非零都需复盘到根因
注销差错率需更正的注销 / 总注销流程设计的可靠性
03 RISK REGISTER

六个最可能翻车的地方

风险早期信号应对
碳数据质量不足农户上传凭证缺失率 > 30%，核证驳回集中在同一环节降低录入门槛（图片 + 语音）、先做小样本核证、把核证要求前置到表单设计
登记簿 API 不稳定签发/转移回调延迟、字段语义不一致适配器层 + 幂等重试 + 人工兜底通道；对账任务兜住最终一致性
碳权益被当作证券用户把它当可交易资产、提出转让需求合同措辞与界面用语双重约束；不提供任何转让入口；必要时调整结构
资金流与实体混同为「方便」让平台账户代收硬性禁止；三个实体独立账户；财务按月出隔离报表
项目供给虚高入驻多但碳基线完成少、融资转化低用转化率而非入驻数作为核心 KPI；提高上架门槛
过早代币化销售或投资人要求「链上化」以显得先进以登记簿 + 合同 + 台账满足需求；代币化作为独立持牌实体的可选项，不影响主线
一句话总结
技术难点不在做一个众筹网站或一个碳台账，而在于用同一套项目 ID 把资本事件和碳事件绑定在同一条时间线上，同时在合同、台账、登记簿三个层面守住「碳权益不是股权、投资不等于买碳」的边界。
