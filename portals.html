六个门户，一套身份

门户不是六个网站，是同一个数据底座的六种视角。用户只登录一次，权限决定他看到哪个世界；同一个项目在不同门户里是同一行记录，只是字段可见范围不同。

01 PORTAL BY PORTAL

每个门户的功能清单

以下是最小可用功能集（MVP+）。标注 写 的模块会产生新的数据记录，标注 读 的只是视图。

P1

项目方门户

PROJECT OWNER
  • 项目仪表盘 — 孵化完成度环、待办清单、融资进度、核证状态
  • 项目注册与诊断 — 6 步表单：主体信息 → 产业链环节 → 碳项目类型 → 基线数据 → 融资计划 → 提交审核 写
  • 碳基线录入 — 结构化表单 + Excel 模板导入；内置因子库自动匹配，缺失项标红 写
  • 融资材料管理 — BP、财务模型、供应链合同、土地/水权证明，版本化上传
  • MRV 任务 — 监测期任务日历、数据上传、IoT 设备绑定、核证方反馈回复 写
  • 投资人关系 — 谁看过项目、谁预约了、问答区、更新推送
设计要点
农户端必须能在手机 + 弱网下完成基线录入：分步保存、离线草稿、图片压缩上传。
P2

社区投资者门户

RETAIL INVESTOR
  • 项目发现 — 按产业链环节 / 地区 / 阶段 / 是否有碳权益筛选，卡片带减排潜力评分
  • 发行页 — 故事、目标、用途、股权结构、碳权益说明、强制风险披露区（不可折叠）
  • 认购流程 — 金额输入 → 合规问卷 → 电子签 → 托管付款 → 状态跟踪 写
  • 我的投资 — 已确认 / 待处理 / 已取消三栏；每条含金额、份额、合同 PDF、碳权益占比
  • 碳权益查看 — 我在这个项目上对应的年度碳权益吨数（含 SPV 穿透比例，只读）
  • 通知中心 — 交割、核证签发、可分配、退出等关键节点推送
设计要点
碳权益必须显示为「合同权利」，而不是「你拥有 X 吨碳信用」。措辞决定证券属性判断。
P3

机构 / 企业门户

INSTITUTION & CORPORATE
  • 数据室 — 文件夹级权限：尽调材料、核证报告、财务模型、供应链合同；水印 + 下载日志
  • SPV / 基金认购 — 认购文件包、KYC、电签、出资进度 写
  • 碳权益台账 — 按项目 / vintage / 标准 / 状态筛选；导出 CSV 与 PDF 读
  • 远期合同管理 — 已签意向、条款清单、交付计划、违约条款提醒
  • 注销指令 — 选择吨数 → 用途声明 → 受益人具名/匿名 → 双重计算校验 → 提交 写
  • 披露支持包 — 一键生成年度碳权益报表（范围三 / 抵消 / 移除分类字段）
设计要点
机构用户不逛网站，他们只来查数。默认落地页是台账，不是首页。
P4

基金管理门户

FUND MANAGER
  • AUM 总览 — 已投 / 未投 / 承诺未到账，按基金与 SPV 分列
  • 投资组合 — 项目级持股比例、估值、股权 + 碳权益双栏
  • 资本调用 — 生成 call notice、按 LP 份额分摊、到期追踪 写
  • NAV 估算 — 季度估值表、方法说明、LP 报表批量生成
  • carry 瀑布 — 两种口径：仅股权收益 / 含碳权益收益；分配顺序可配置
  • 退出管理 — 退出事件登记、对价拆分、分配执行 写
设计要点
carry 口径必须在基金合同里先定义，系统只做可配置执行，不做默认假设。
P5

MRV / 核证方门户

VERIFIER
  • 任务队列 — 待接单 / 审核中 / 待签发 / 已驳回，按截止日排序
  • 数据审核台 — 监测报告 + 原始凭证 + IoT 时序并列对照，逐项标注
  • 核证报告 — 结构化表单 + PDF 上传，签发量填写即触发守恒校验 写
  • 驳回与整改 — 问题清单回传项目方，形成整改闭环
  • 历史记录 — 我签发过的所有批次与登记簿状态
设计要点
核证方不能看到项目的融资金额与股权结构——避免核证独立性问题。权限按字段裁剪。
P6

平台运营后台

PLATFORM ADMIN
  • 项目审核 — 入驻审核、材料完整性检查、上/下架
  • 费率配置 — 平台服务费、核证费、托管费、碳权益服务费
  • 合规工作流 — 发行豁免配置、KYC 等级、审批流设计器
  • 争议处理 — 工单、证据链、处理结论留痕
  • 风险看板 — 守恒告警、核证驳回率、注销差错、逾期任务
  • 报表中心 — 项目供给、资本栈、碳权益、风险四组指标导出
设计要点
管理员不得直接修改已签发的吨数或已注销记录。所有更正走「红冲 + 重开」双记录流程。

关键设计
核证方看不到融资信息，机构看不到其他机构的持仓，项目方看不到其他项目的碳权益分配——三种「互盲」共同构成独立性基础。任何一次越权访问都要在生产日志里可查。
03 SHARED CORE

六种视角，四条共享规则

R1

同一身份

一个自然人/机构一个 identity_id，可同时是社区投资者与机构 LP；不同角色挂不同 KYC 等级，不重复开户。

R2

同一项目

项目只有一个 project_id。门户之间不复制数据，只做视图投影；项目改名，六个门户同时改。

R3

同一数字

碳吨数、金额、份额只有一个来源（业务表 + 事件流）。报表不做二次计算，避免同数不同源。

R4

同一措辞

「碳权益」不叫「碳资产」，「认购」不叫「购买」。术语字典统一维护，前端文案从字典取，禁止硬编码。
