01 DESIGN PRINCIPLES

四条设计原则，决定后面每一个页面长什么样

这四条不是价值观口号，是硬性产品约束。任何功能设计与之冲突，功能改，原则不改。

01

分离但耦合

投资协议与碳权益协议分开计价、分开记账，但在界面上合成同一个「项目权益包」——用户看到一份资产，后台看到两套科目。

02

碳资产不可凭空产生

只有经过 MRV → 第三方核证 → 登记簿登记 → 所有权转移或注销的减排量，才允许进入碳权益层。平台上任何手工录入的吨数都只是预备档案。

03

合规隔离

证券发行、基金管理、碳资产服务由不同法人承接。平台只做基础设施：一套技术系统，三条法律与资金流，绝不混同。

04

一个项目，一条时间线

融资交割、核证签发、权益分配、注销、退出——全部写入同一条事件流。投后数据自动沉淀，不靠人肉对齐 Excel。

02 REFRAME

三个既有页面 → 一条资本栈 + 一条碳脊柱

平台化的关键不是界面统一，而是数据模型统一。原来三个站点各自持有的「项目」，在平台里必须是同一条主键记录。

明确不做
平台不是碳注册处（登记簿仍归 Verra / Gold Standard / Puro.earth）；不是碳交易所（不做二级撮合）；不托管代币化碳资产的私钥；不承诺任何披露合规结论。定位越窄，越能通过监管审视。

04 THE CORE PICTURE

一条脊柱，两条轨道

左边是钱怎么进、怎么退；右边是碳怎么被证明、怎么被分配。中间那根竖线是项目 ID——它让两边永远对得上。

05 SEQUENCING

四个阶段，先跑数据模型再叠加资金流

MVP 阶段就引入代币化或链上交易，会把合规复杂度提前引爆。顺序即风险控制。

06 THE HARD LINE

技术难点不在页面，在边界

做一个众筹网站不难，做一个碳台账也不难。难的是：用同一套项目 ID 把资本事件和碳事件绑在一条时间线上，同时在合同、台账、登记簿三个层面守住「碳权益不是股权、投资不等于买碳」。

看碳权益层怎么守 → 看合规怎么隔离
红线 1
同一吨减排量，只能有一个去向。计入企业范围三、分配给权益持有人注销、对外出售——三选一，台账层强制排他。
红线 2
注销在登记簿执行后不可逆。平台台账立即锁定，任何编辑请求变为新增更正记录。
红线 3
碳权益作为投资协议的附属合同权利，不单独证券化、不二级转让。一旦可自由转让，可能构成另类投资产品。
